# C Practice — UI system

A workbench, not a brochure. The visitor is a student mid-task: they read a problem,
write C, and wait for a verdict. In the vocabulary of the `impeccable` skill this is an
**Operate** surface — scanability, consistency and the real usage scene outrank
expression, and the brand lives in precise details. Every rule below follows from that.

Adopt the aesthetic devices of *Persuade* surfaces (glowing mesh gradients, uppercase
eyebrow pills above headings, nested "double-bezel" cards, `transition: all`,
multi-effect hover stacks) only if the surface stops being a workbench.

## Where the system lives

| File | Owns |
|---|---|
| `frontend/tokens.css` | **The system.** Every colour, font, space, radius, shadow, duration and z-index. The first comment carries the macrostructure stamp. |
| `frontend/src/styles/app.css` | Base rules, the component layer (`.btn`, `.surface`, `.sheet`, `.well`, `.tag`, `.verdict-*`, `.ratio`), and the reduced-motion block. Carries the pre-emit critique stamp. |
| `frontend/src/index.css` | The entry stylesheet. **Append-only**: keep the Tailwind import first, then tokens, then app.css. |
| `.hallmark/log.json` | Design-run memory. Append an entry when you change the macrostructure or theme. |

Components reference tokens by name — `text-[var(--color-muted)]`,
`var(--space-md)`, `backgroundColor: 'var(--syntax-keyword)'`. **Never inline a hex, an
`oklch()`, or a `font-family` in a component or a stylesheet outside `tokens.css`.** If a
value you need doesn't exist, lift it into the token block as a named variable first.
This is checkable and should be checked:

```bash
grep -rnE "#[0-9a-fA-F]{3,8}\b|oklch\(|rgba?\(|hsla?\(" frontend/src --include=*.tsx --include=*.ts | grep -v "var(--"
grep -rn "font-family" frontend/src --include=*.tsx --include=*.ts
# both must print nothing
```

## Rules, each with the failure it prevents

**One accent, under ~3% of the viewport.** The accent marks the single primary action
and nothing else. Reserve `--color-accent-ink` for text on an accent fill and verify it
clears 4.5:1 — the classic bug is a filled button that keeps the body ink colour.

**Never signal by colour alone.** Every verdict is a mark **plus** a word
(`StatusMark` + "Passed"), and the score bar encodes its value in *length* as well as
hue, with an `aria-label` carrying the number. Assume a greyscale print and a screen
reader.

**No uppercase eyebrows and no emoji.** `text-transform: uppercase` and
pictographic glyphs were removed from this app deliberately; both are among the most
reliable "generated by a model" tells. Carry emphasis with weight, colour or space.
Decorative SVG gets `aria-hidden` (see `StatusMark`).

**Sizes stay on the scale.** `--text-micro` is the floor. Controls are **44px** tall
(`min-height: 2.75rem`) — `.btn` and `.field` share it exactly so a form row never
mixes two heights. Controls declare `line-height: 1` because they sit in mixed flex
rows and inheriting the body's 1.55 breaks the row's vertical rhythm.

**Radii encode hierarchy, not decoration**: `--radius-micro` (6px) tags, `--radius-control`
(10px) buttons and inputs, `--radius-surface` (16px) cards, `--radius-sheet` (22px) the
largest surface. One radius on everything is the tell. **Never nest a card inside a
card** — there is one containment layer.

**A heading never shares a row with a label, number or kicker.** The title goes on its
own line; metadata stacks beneath it. This was violated three times before it was fixed,
and the shape reads as a template within seconds.

**Controls are always vertically centred, and clickable text never wraps**
(`white-space: nowrap` on `.btn`, `align-items: center` on mixed rows).

**Body text is at least 4.5:1 against its *effective* background; large text, icons and
focus rings at least 3:1.** Verify by computed style, not by eye — `--color-muted` on
`--color-surface` is a different pair from `--color-muted` on `--color-surface-2`.

## Hover is gated; press is not

Every hover rule in the app lives inside one query:

```css
@media (hover: hover) and (pointer: fine) { … }
```

A touch device synthesises `:hover` on tap, so an ungated rule leaves a row stuck in its
hover state after the finger lifts. `:active` stays **ungated** — the press is the touch
feedback, and it should land on pointer-down, not on release.

Hover changes **one** thing (surface). It must not stack a translate with a colour change
and a scale. The lift belongs to `:active`, nowhere else.

## Content must never depend on an animation to become visible

This is the rule with the sharpest teeth. An entrance declares its hidden frame in the
**keyframes** and uses `animation-fill-mode: backwards`, so the element's own resting
style is the visible one:

```css
.reveal {
  animation: reveal var(--dur-long) var(--ease-out) backwards;
  animation-delay: calc(var(--i, 0) * 55ms);
}
@keyframes reveal { from { opacity: 0; transform: translateY(8px); } }
```

The tempting alternative — `opacity: 0` in the rule plus `forwards` — makes the entire
page's visibility contingent on an animation completing. Disable animations for any
reason (a stalled document timeline, an aggressive reduced-motion policy, a stripped
stylesheet) and the app renders blank. This was observed, not theorised.

For the same reason **the verdict panel has no entrance animation at all**: it is what
the student just waited for, so it is readable on the frame it arrives. And the score bar
has none either, because its length *is* the data — an animated fill can sit at zero next
to a "7/7", which states something false. Decorative motion is welcome here; motion that
can misreport is not.

Reduced motion needs **no parallel rules**. The universal block sets
`animation-duration: 0.01ms !important` and `animation-delay: 0ms !important`, which turns
every entrance into an instant appearance and drops the stagger. Because each animation
keeps its hidden frame in the keyframes, that one block is sufficient — do not add a
`.reveal`-specific reduced-motion copy that can drift out of sync.

Keep stagger intervals in the 30–80ms band (currently 55ms) and UI transitions under
300ms; press feedback belongs in the 100–160ms band.

## The editor is part of the system

`frontend/src/components/Editor/editorTheme.ts` drives CodeMirror from the same tokens
via `var(--syntax-*)`, so it follows the system appearance with no JavaScript colour
maths. Two traps are already paid for and must stay paid for:

- **`theme="none"` on `<CodeMirror>` is load-bearing.** `@uiw/react-codemirror` defaults
  `theme` to `'light'` and pushes its own theme whose entire content is
  `backgroundColor: '#fff'`, scoped to generated `ͼ…` classes. On a dark palette that
  painted near-white text on white. Passing `'dark'` instead would just swap in `oneDark`
  and reopen the same drift.
- **`className="h-full"` is also load-bearing.** The library wraps the editor in a div at
  content height, so `.cm-editor { height: 100% }` collapses to the number of lines and
  leaves a band of bare card under the code.

Also declare `color-scheme` and `scrollbar-color` explicitly — `color-scheme` alone does
not restyle scrollbars in every embedding, and without them a dark app gets light
scrollbar chrome.

## Verifying a change

Run typecheck and build, then **drive the real page** — the build passing says nothing
about whether the UI renders. Read the `ui-verification` skill for the full method and
its traps. The short version, evaluated in the live page:

```js
// 1. Are all tokens resolving, and is nothing animating with `all`?
// 2. Does any visible element still use uppercase or an emoji?
// 3. Contrast of every text node against its *effective* background.
// 4. Does the page scroll horizontally? (overflow-x: clip on html AND body)
// 5. Any heading on the same row as a label?
```

Before you claim a visual result, read `ui-verification` — screenshots in a stalled
webview return stale frames, and an animation frozen at progress 0 looks identical to a
broken layout.

## When a design task arrives

1. Read `frontend/tokens.css` and `frontend/src/styles/app.css` first. They are the truth
   about the system; this document is only the commentary.
2. Classify the surface (Operate / Read / Persuade). If it is not Operate, say so — the
   rules above are tuned for Operate and some are deliberately overridden there.
3. Make the change with tokens, not literals.
4. Verify with the recipe above before reporting. Quote the numbers you measured.
